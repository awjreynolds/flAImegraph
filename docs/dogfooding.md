# Dogfooding flAImegraph

The project's own agent work is a required validation case. The user authorized publishing this conversation's derived usage and cost evidence on 6 September 2026. The [first public review record](https://github.com/awjreynolds/flAImegraph/issues/9#issuecomment-5560891854) links the frozen capture, monetary projections and their verification limits.

At meaningful implementation milestones:

1. Identify the issue, intended outcome, repository revision and capture interval before interpreting the run. Preserve the original scope and any later changes.
2. Capture this project's execution and delegated work using the available native evidence. Preserve observation identity, source version and missing coverage. Shared or inherited work must not be counted twice.
3. Apply a named, versioned cost basis. Keep measured quantities separate from enterprise-rate scenarios and actual financial charges.
4. Export through the common contract once implemented, then render with independent existing tools. Reconcile observation, agent and work-item totals, and inspect the monetary widths and drilldown.
5. Attach a sanitized evidence summary, reproducible artifact references, acceptance outcome and discovered gaps to the relevant review issue. Retain failed and incomplete work in the measurement record.

Until the common contract exists, the current prototypes are baseline fixtures. They do not establish a completed cross-harness standard or an always-on collector. Capture checkpoints must avoid overlap being interpreted as new expenditure.

The initial Codex fixture contains 177 observed calls through 2026-09-06T16:36:00Z. Its selected public Enterprise scenario yields a $41.046242 model-token subtotal. It is a partial, reproducible measurement example, not the total cost of this project or a training dataset adequate for prediction. See the [valuation artifact](https://github.com/awjreynolds/flAImegraph/tree/codex/prototype-capture-depth/prototypes/enterprise-valuation) for assumptions and exclusions.

Dogfooding complements adversarial fixtures and a second harness. Our own workflow alone cannot establish portability, forecasting accuracy or suitability for other teams. The [interchange specification](research/interoperable-export-contract.md), [comparative validation](https://github.com/awjreynolds/flAImegraph/issues/20) and [calibration dataset](https://github.com/awjreynolds/flAImegraph/issues/22) retain those separate requirements.
