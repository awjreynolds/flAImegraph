# Operation depth, version 0.3

The acceptance boundary is a profiler that records and exposes the individual operations within an agent: directory enumeration, each file read, edits, searches, tests, hooks, delegation and model requests. Nesting follows recorded execution containment. A single opaque shell command does not prove its internal file operations.

Public test seams are capture/recorder, native import, report generation/validation and export/CLI. These are the seams selected under the user's instruction to make implementation decisions autonomously. Implement through red/green slices and obtain independent review.

1. Introduce a versioned operation sidecar composing with the frozen cost evidence and context formats. Require stable identities, provenance, explicit unknowns, cycle and duplicate rejection, and honest coverage.
2. Provide a zero-model-call recorder with asynchronous nesting, concurrency, real file/directory wrappers, error preservation, bounded capture and explicit loss reporting. Record bytes actually read/returned separately from context insertion. Record routing decisions as observable policy facts, never inferred internal reasoning.
3. Import structured native tool events conservatively. Correlate IDs, preserve gaps, and expose opaque shell boundaries. Establish at least one practical live harness integration.
4. Produce an execution tree and chronology containing all recorded operations, including zero and unknown monetary cost. Produce standard monetary flamegraphs with genuine nested ancestry and exact conservation. Show an explicitly estimated source-allocation projection separately; keep residuals and unbound costs visible.
5. Provide an inspectable browser experience with operation search, paging, ancestry, timing, IO, model identity, routing and consuming context links. Support 5,000 actual file operations without constructing an unbounded visible DOM.
6. Capture actual file work, edit and test execution; verify deep nesting, deterministic replay, errors/concurrency, privacy and overhead. Include sanitized native real-work evidence and an explicit direct-versus-summary comparison that does not claim unsupported savings.
7. Review, correct, test, document and publish the integrated release; record decisions and remaining capture limits for the morning summary.

Recording and deterministic classification run as ordinary code with no required LLM requests. Optional semantic classification or summary routing belongs to the measured workload and must record its own model usage. A file read has no inherent model bill; costs arise when models consume material. Context allocation conserves a selected valuation but is neither per-file billing nor a causal savings estimate.
