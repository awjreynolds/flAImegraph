# Gemini CLI and OpenCode: native capture and concrete profilers

Research date: 6 September 2026. Bounded static audit of public source and official documentation. No installations, model calls, private-session access, or runtime validation. Versions below are inspected source manifests, not guarantees about the version installed on any machine.

**There are useful profilers for both harnesses.** The strongest candidates answer different questions: Gemini's own developer tools inspect requests, Skiagram produces token/cost views from stored chats, OpenCode Trace inspects provider exchanges, and LangSmith's official OpenCode plugin creates nested agent traces. None of this audit establishes complete ticket-level accounting or exact context-component token attribution.

## Four concrete options

| Tool | Actual harness capture | Useful analytical depth | Accounting and completeness limit |
| --- | --- | --- | --- |
| **Gemini CLI DevTools**, with the separate native OTel → Genkit UI route | First-party network/console hooks; native model/tool spans | Request/response bodies, streaming chunks, durations, session selection, JSONL import/export; Genkit shows operation traces | Inspector, not a spend ledger; estimated context breakdown is not exact tokenizer attribution |
| **Skiagram 0.1.2** | Dedicated Gemini CLI chat-JSONL adapter | Token/cost flamegraphs, model and token-category breakdown, tool/thought content, context estimates | Main-chat discovery excludes current nested subagent files; no runtime billing reconciliation verified |
| **OpenCode Trace plugin 0.0.7** | OpenCode hooks plus wrapped provider HTTP fetch | Raw request/response, streaming data, request-to-request conversation changes, input/cache/output totals, session parent relationships | Header/protocol-dependent capture; file-recovery “reconciliation” is not token/bill reconciliation |
| **@langchain/langsmith-opencode 0.1.0** | Official OpenCode chat/event plugin | Completed user turn → assistant/model runs → tools and linked subagent runs; prompts, reasoning and attachments | Incomplete turns omitted; inspected usage mapping needs a cache-normalization check against current OpenCode |

These are harness integrations, not assertions that a generic model SDK can observe arbitrary coding-agent activity. DevTools and Genkit are separate UIs; enabling one is not equivalent to obtaining every capability of the other.

## Gemini CLI: substantial native evidence already exists

Inspected Gemini revision: `85aca163f6c73ac6ce380b5447359146b8adcae4` (4 September 2026). The DevTools package manifest is `0.60.0-nightly.20260901.g0bd1d4397`, so these findings include current development code rather than only a stable-release feature claim. Its concrete network schema contains request ID, session ID, URL, headers/body, timestamped stream chunks, response status/body/duration and errors. The UI offers Network and Console tabs and JSONL import/export. [Manifest](https://github.com/google-gemini/gemini-cli/blob/85aca163f6c73ac6ce380b5447359146b8adcae4/packages/devtools/package.json#L1-L10), [network schema](https://github.com/google-gemini/gemini-cli/blob/85aca163f6c73ac6ce380b5447359146b8adcae4/packages/devtools/src/types.ts#L7-L30), [UI import/export](https://github.com/google-gemini/gemini-cli/blob/85aca163f6c73ac6ce380b5447359146b8adcae4/packages/devtools/client/src/App.tsx#L105-L215)

The model wrapper creates `LLMCall` spans and records request model, system instructions, tool definitions, input/output and provider usage metadata. Rich attributes depend on telemetry settings. The documented native integration explicitly supports viewing model, scheduler and tool traces in Genkit, Jaeger or Google Cloud; this is a first-party instrumentation path, not a guessed backend compatibility claim. [Model wrapper](https://github.com/google-gemini/gemini-cli/blob/85aca163f6c73ac6ce380b5447359146b8adcae4/packages/core/src/core/loggingContentGenerator.ts#L356-L417), [native Genkit workflow](https://github.com/google-gemini/gemini-cli/blob/85aca163f6c73ac6ce380b5447359146b8adcae4/docs/local-development.md#tracing), [official telemetry settings](https://github.com/google-gemini/gemini-cli/blob/85aca163f6c73ac6ce380b5447359146b8adcae4/docs/cli/telemetry.md)

An especially relevant implementation is `estimateContextBreakdown`: it estimates disjoint buckets for system instructions, tool definitions, conversation history, individual non-MCP tool call/response content, and MCP content. Some components use serialized length divided by four. This offers a concrete starting point for explaining context composition, while its own semantics remain **estimates**, not provider-verified per-component tokens. [Context estimator](https://github.com/google-gemini/gemini-cli/blob/85aca163f6c73ac6ce380b5447359146b8adcae4/packages/core/src/core/loggingContentGenerator.ts#L59-L145)

Native chat recording stores per-message input, output, cached, thoughts, tool and total usage fields. Current subagent files live beneath a directory named for the complete parent session ID, unlike main `session-…jsonl` files. The executor preserves the main-agent session identity in its context. These are useful lineage clues, but directory ancestry alone is not every nested delegation edge. Rewind and metadata-update records also mean “sum every JSONL line” is not a valid parser. [Subagent paths](https://github.com/google-gemini/gemini-cli/blob/85aca163f6c73ac6ce380b5447359146b8adcae4/packages/core/src/services/chatRecordingService.ts#L478-L538), [usage fields](https://github.com/google-gemini/gemini-cli/blob/85aca163f6c73ac6ce380b5447359146b8adcae4/packages/core/src/services/chatRecordingService.ts#L744-L765), [executor context](https://github.com/google-gemini/gemini-cli/blob/85aca163f6c73ac6ce380b5447359146b8adcae4/packages/core/src/agents/local-executor.ts#L134-L145)

**Skiagram's Gemini adapter is real but narrower.** At revision `5af260f40040581e6fa1e8d76b6f363d6142d12a`, it reads this JSONL family and collapses repeated Gemini message IDs using latest content and component maxima. Cached input is separated from input; thoughts are retained separately from candidate output. However discovery requires a filename beginning `session-` directly inside `chats`, excluding the native nested subagent recordings above. Session parent and subagent fields remain empty. Its flamegraphs therefore cannot be presented as complete orchestration totals without adapter changes. [Discovery predicate](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/gemini.rs#L86-L103), [session construction](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/gemini.rs#L192-L219), [message deduplication](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/gemini.rs#L330-L350), [token normalization](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/gemini.rs#L444-L466)

## OpenCode: trace both execution and provider exchanges

Native OpenCode revision `337fd144d2ba144743368f78d9579a99cce175bd` stores session parent IDs, token categories and costs in SQLite. Its processor emits `step-finish` usage/cost parts and exposes retry attempt/status information. Its token normalization explicitly subtracts cache read/write from input and reasoning from output, producing separate buckets. A consumer must preserve those meanings when translating to conventions where input/output totals include their subsets. [Session table](https://github.com/anomalyco/opencode/blob/337fd144d2ba144743368f78d9579a99cce175bd/packages/core/src/session/sql.ts#L22-L51), [step finish](https://github.com/anomalyco/opencode/blob/337fd144d2ba144743368f78d9579a99cce175bd/packages/opencode/src/session/processor.ts#L435-L470), [retry status](https://github.com/anomalyco/opencode/blob/337fd144d2ba144743368f78d9579a99cce175bd/packages/opencode/src/session/processor.ts#L674-L687), [normalization](https://github.com/anomalyco/opencode/blob/337fd144d2ba144743368f78d9579a99cce175bd/packages/opencode/src/session/session.ts#L338-L376)

**OpenCode Trace** (`97dc89b6d71094b807d7a4b6af240cd1628b3ad3`) is particularly useful for seeing what was actually sent. The interceptor associates a request through recognized session headers, clones its body, assigns a sequence and records timestamps. Session hooks retain parent IDs and Task-generated child sessions; provider parsers cover OpenAI chat/responses and Anthropic messages. The query layer compares successive conversations and separately sums cache-hit input, cache-miss input and output. [Request capture](https://github.com/aixmoyu/opencode-trace/blob/97dc89b6d71094b807d7a4b6af240cd1628b3ad3/packages/plugin/src/plugin-instance.ts#L208-L215), [body and sequence capture](https://github.com/aixmoyu/opencode-trace/blob/97dc89b6d71094b807d7a4b6af240cd1628b3ad3/packages/plugin/src/plugin-instance.ts#L258-L321), [child-session hooks](https://github.com/aixmoyu/opencode-trace/blob/97dc89b6d71094b807d7a4b6af240cd1628b3ad3/packages/plugin/src/trace.ts#L86-L132), [conversation changes and totals](https://github.com/aixmoyu/opencode-trace/blob/97dc89b6d71094b807d7a4b6af240cd1628b3ad3/packages/core/src/query/session.ts#L164-L252)

This is deeper request evidence than a usage dashboard, but it is still bounded by intercepted transports, supported parsers and those headers. The inspected hooks log tool activity; they do not by themselves establish a complete timed tool-span tree. Requests may reveal retries, but this audit did not find an explicit retry-of relationship in the examined capture path. Its `FallbackReconciler` restores failed file writes; the name should not be mistaken for provider-billing reconciliation. [Recovery implementation](https://github.com/aixmoyu/opencode-trace/blob/97dc89b6d71094b807d7a4b6af240cd1628b3ad3/packages/plugin/src/fallback-reconciler.ts#L94-L139)

**LangSmith's official plugin** (`dc9e68c982a8e4d173e184ff2bf41a4eddd81d88`, package 0.1.0) is the strongest inspected ready-made execution-tree integration. It builds a root per completed user turn, assistant/model children, tool inputs/outputs/errors/timing and subagent traces; system prompts and session metadata are captured through OpenCode hooks. Completion requires a stopping `step-finish`; incomplete turns are not submitted, and shutdown flush drains posted batches rather than constructing missing turns. Therefore complete-trace visibility is not evidence of complete spending capture. [Official integration](https://docs.langchain.com/langsmith/trace-with-opencode), [run tree](https://github.com/langchain-ai/langsmith-opencode/blob/dc9e68c982a8e4d173e184ff2bf41a4eddd81d88/src/tracer.ts#L381-L469), [completion gating](https://github.com/langchain-ai/langsmith-opencode/blob/dc9e68c982a8e4d173e184ff2bf41a4eddd81d88/src/tracer.ts#L573-L615), [flush](https://github.com/langchain-ai/langsmith-opencode/blob/dc9e68c982a8e4d173e184ff2bf41a4eddd81d88/src/tracer.ts#L486-L489)

There is a specific translation concern: the plugin exports `input_tokens = stepFinish.tokens.input`, and total input/output/reasoning excludes cache buckets, while current OpenCode's input bucket is already cache-exclusive. For input 1,000 of which 600 is cached and output 100, native buckets are input 400, cache 600, output 100; this mapping emits total 500 with cache 600 in details, instead of total 1,100. This is a source-level incompatibility to test before trusting backend totals; no downstream compensation was established here. [Plugin usage mapping](https://github.com/langchain-ai/langsmith-opencode/blob/dc9e68c982a8e4d173e184ff2bf41a4eddd81d88/src/tracer.ts#L266-L286), [native bucket definition](https://github.com/anomalyco/opencode/blob/337fd144d2ba144743368f78d9579a99cce175bd/packages/opencode/src/session/session.ts#L361-L376)

## What to reuse

For **Gemini request/context investigations**, start by evaluating the native DevTools and OTel/Genkit capture on synthetic sessions; retain reported usage separately from estimated component sizes. For **OpenCode delegation investigations**, evaluate the LangSmith execution tree alongside a provider-exchange recorder such as OpenCode Trace. For **portable flamegraphs**, Skiagram demonstrates an existing export route, with its Gemini child-discovery gap explicitly accounted for.

The common acceptance test should include a cached request, streamed repeated records, a retry, cancellation before completion, and a nested subagent. Verify which observations each collector retains and whether independently reconstructed totals conserve usage. These options materially reduce the amount of UI and integration work needed; they do not remove the need for a shared accounting contract or prove exact segment-level token provenance.
