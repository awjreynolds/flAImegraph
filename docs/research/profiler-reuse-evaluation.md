# Reusing existing agent profilers for deep Codex token analysis

Research date: 6 September 2026. Static source audit; no personal transcripts, installs, provider calls, or execution of either project. Conclusions describe the pinned revisions, not every release. Findings below are code-path deductions, with constructed counterexamples where useful; upstream test presence is distinguished from tests run here.

**Recommendation:** reuse existing formats, viewer components, and selected parser ideas. Neither inspected Codex adapter should currently become the authoritative accounting layer unchanged. AgentSight offers richer semantic operation projections; Skiagram offers a clearer separation of reported usage, context estimates, and estimated prices. Both have specific correctness and detail gaps for this effort.

## Sources and maturity

Its CLI supports pprof, folded, SVG, and JSON outputs; token view and regex tagging are defaults. Version numbers indicate published-package structure, not accounting validation. [Manifest](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/pprof/Cargo.toml#L1-L19), [CLI](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/pprof/src/main.rs#L60-L96)
- Skiagram: `5af260f40040581e6fa1e8d76b6f363d6142d12a`, workspace version **0.1.2**, MIT, separate core and CLI crates, with Inferno used for SVG rendering. It has synthetic Codex parser snapshots and accounting assertions. These are useful foundations; this audit did not run its suite or establish production adoption. [Manifest](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/Cargo.toml#L1-L55), [Codex snapshot tests](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/tests/codex_snapshot.rs#L24-L72)

The bounded comparison concentrates on these two implementations because both contain inspectable Codex-local-log paths and token flamegraphs. Traceburn and AgentMeasure were not audited; absence from this report is not an assessment of their capabilities.

## What their graphs actually represent

| Aspect | AgentSight agentpprof | Skiagram |
| --- | --- | --- |
| Default hierarchy | task → skill → phase → action → object → repeat → result → outcome → token | project → session → model → token type |
| Meaning of task/session | Task labels derived from prompts and active plans | Session grouping, optionally folded into a recorded parent |
| Measures | Separate token, operation, time, file and network views | Tokens or estimated micro-USD |
| Reusable feature | Configurable semantic stacks, field rules, filters and evidence labels | Core/viewer separation, disjoint usage buckets, explicit unpriced-request count |
| Missing for trusted Codex accounting | Reliable call usage attribution and category conservation | Duplicate-snapshot handling and production reconciliation |
| Deep lineage | Spawn intent can enter a tool's task path, without joining child usage | Model supports parent sessions, but Codex adapter does not populate them |

AgentSight's default frames are **classifications of operations**, not the observed parent/child model-call tree. Its task state holds a user-derived root and at most one active plan step; a new non-continuation prompt replaces that root. A `spawn_agent` tool adds its task name/message to that tool's path. This can make work categories readable, but does not establish the hierarchy `epic → ticket → conversation → delegated execution → model call`. [Default stack](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/pprof/src/profile.rs#L80-L90), [task state and spawn path](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/parser.rs#L411-L489)

Its token samples attach a token-category leaf to each LLM response, while available pprof labels preserve session, source kind, evidence hash, timestamp and selected lifecycle fields. The evidence hash derives from session plus response-text hash; identical responses in the same session can share it. It is useful for navigation but cannot serve alone as a globally unique billing-observation ID. [Token projection](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/pprof/src/profile.rs#L775-L813), [label allowlist](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/pprof/src/profile.rs#L209-L237)

## AgentSight: Codex accounting findings

**Cached input is treated inconsistently.** Session-summary conversion subtracts cached input from input, creating disjoint buckets. Response attribution instead copies the full `input_tokens` alongside `cached_input_tokens`; `token_components()` emits both additively. For input 1,000, cached input 600 and output 100, the normal response-based graph receives 1,700 tokens rather than 1,100. This is a concrete conditional overcount where cached input is a subset of reported input. [Summary conversion](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/parser.rs#L2627-L2639), [response assignment](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/parser.rs#L880-L903), [component emission](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/types.rs#L144-L168)

**A usage event is attached to the latest unpopulated assistant response.** It prefers `last_token_usage`, falls back to cumulative `total_token_usage`, and performs no cumulative differencing in that branch. Tool-only or reasoning-only model completions need not produce an assistant-message response object there. Repeated usage may be ignored when the latest response already has a total, but that is a response-order heuristic, not request identity or snapshot reconciliation. If cumulative fallback values of 100 and 220 attach to two responses, summing them gives 320 rather than 220. [Usage handling](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/parser.rs#L853-L947), [response-item handling](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/parser.rs#L953-L1102)

**Fallback is all-or-nothing.** A session summary creates synthetic LLM entries only when the LLM list is empty. Existing response entries with incomplete or zero usage prevent that fallback from recovering the residual. Unknown components become a synthetic weight of **one** under `unknown`; large values above hardcoded thresholds are dropped, with total-only fallback labelled `estimate`. Those choices keep a graph drawable but do not conserve measured tokens or preserve the distinction between unknown and one consumed token. [Session fallback](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/pprof/src/session.rs#L226-L251), [component policy](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/types.rs#L144-L168)

**Deduplication helps split messages but is not ledger identity.** Source IDs are used where present; Codex response objects assign an empty source ID. The fallback merges adjacent identical text under the same prompt within one second and takes component maxima. This can merge duplicate representations, but also cannot distinguish all genuinely repeated completions or later reimports. [Deduplication](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/parser.rs#L1133-L1187), [Codex empty source ID](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/parser.rs#L1080-L1101)

**Fork handling is a useful starting point.** Parent/fork metadata causes copied history to be skipped until an eligible `task_started`, whose start is extracted from `started_at` or UUIDv7 `turn_id` and compared with session creation time. A specific upstream test covers this boundary. However the profile `SessionRecord` has no parent-thread field; conversion does not reconstruct child execution beneath its spawning operation. A child lacking the expected boundary can remain excluded. [Boundary](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/parser.rs#L562-L627), [boundary test](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/session/src/parser.rs#L4810-L4842), [record conversion](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/pprof/src/session.rs#L16-L30)

## Skiagram: clearer buckets, incomplete Codex evidence handling

The Codex adapter maps input/cache/reasoning to disjoint optional usage fields and preserves compaction as an event. It emits a usage-bearing assistant event for every `token_count` containing `last_token_usage`, tagging it with the current model. Unlike AgentSight, it does not substitute cumulative usage when last usage is absent. [Usage and compaction](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/codex.rs#L363-L413), [disjoint mapping](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/codex.rs#L468-L500)

However, those events have no request ID. The downstream dedup pass gives every such event its own line key. Two identical token-count snapshots therefore remain two billable records. Cumulative totals are deserialized into an unused field, so the documented reconciliation invariant is not enforced by the production parser. Its synthetic test proves one fixture sums correctly; it does not establish correctness for repeated notifications, inherited history or counter resets. [Dedup keys](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/analysis/dedup.rs#L112-L150), [unused cumulative field](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/codex.rs#L546-L566)

The Codex session begins with `parent_session: None` and empty subagents; metadata handling reads working directory and model, not parent/fork lineage. It scans the transcript without AgentSight's ownership boundary. Its ID is the filename stem rather than embedded metadata ID. The flame renderer shortens that ID to eight characters: conventional `rollout-…` filenames consequently all yield `rollout-`, merging session slices within the same higher-level grouping. Totals can survive that display collision while drilldown identity does not. [Session construction](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/codex.rs#L138-L158), [filename ID](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/codex.rs#L222-L229), [metadata](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/codex.rs#L258-L281), [short label](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/analysis/flame.rs#L80-L89)

## Depth: context, retries and time

Skiagram has a useful context-analysis model: reported request input totals are separate from transcript-content estimates using characters divided by four, with source and tool-server breakdowns. But its Codex adapter ignores `function_call_output` and reasoning response items, and treats non-assistant message roles as user-side input. Its generic context feature therefore cannot provide a complete Codex tool-result or system/developer breakdown from this adapter. Nor does a transcript-size estimate establish what each request actually retained, truncated, cached or resent. [Context model](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/analysis/context.rs#L1-L35), [Codex response handling](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/adapters/codex.rs#L285-L350)

Neither audited profile path models semantic context segments with stable identities and per-request residency, or provider retry attempts with explicit retry-of relationships. AgentSight labels consecutive identical tool signatures in the operation view; Skiagram flags a candidate storm at five requests with gaps no greater than fifteen seconds. These are useful investigation hints, not proof of waste or retries. [AgentSight repeat heuristic](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/pprof/src/profile.rs#L680-L700), [Skiagram thresholds](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/analysis/anomaly.rs#L42-L48)

AgentSight's time view assigns each event the gap until the next event, truncated to seconds with a one-second minimum and a one-second final event. It must not be described as measured model execution duration or critical-path time. Skiagram cost export accumulates floating-point micro-USD by selected path and rounds on emission; changing grouping can change rounding. Its unpriced-request counter is worth retaining, while exact reconciliation requires an upstream rounding contract. [Time projection](https://github.com/eunomia-bpf/agentsight/blob/bb99b66f8f98e4b9f8b1769a3da0a8fbbe26b6c3/ext/pprof/src/profile.rs#L921-L936), [cost aggregation and rounding](https://github.com/TanvirAnjumApurbo/skiagram/blob/5af260f40040581e6fa1e8d76b6f363d6142d12a/crates/skiagram-core/src/analysis/flame.rs#L265-L351)

## Bounded route to reuse

1. Define a small, synthetic conformance corpus before choosing either adapter: duplicate token notifications, cumulative-only reports, model changes, cache subsets, tool-only completions, forked history, missing terminal usage, and genuine repeated calls.
2. Preserve source observations and ownership boundaries; reconcile cumulative and last-usage evidence without assuming that every notification is a new call. Keep unexplained residuals explicit.
3. Maintain the execution graph separately from semantic classifications and ticket allocation. Do not turn content hashes or shortened display names into financial identities.
4. Generate existing pprof/folded exports from reconciled measures. Reuse AgentSight's configurable projections or Skiagram's viewer plumbing after conservation checks, keeping classifications and context estimates visibly distinct from reported usage.
5. Add deep context analysis only to the precision the captured source supports. Exact per-segment token attribution needs serialized-request evidence and tokenizer/provider semantics; richer colours cannot recover absent evidence.

This supports extending a proven visualisation ecosystem while treating the hard work as evidence normalization, lineage, and accounting semantics. It does not yet justify adopting an entire upstream application or announcing an industry standard.
